# Configuration

## ServiceConfig

Each registered microservice gets a `ServiceConfig` DTO that holds connection and mapping details.

| Property | Type | Description |
|----------|------|-------------|
| `name` | string | Service identifier |
| `baseUrl` | string | Base URL of the microservice API |
| `apiKey` | string | API key for Bearer auth |
| `responseMapping` | ResponseMapping | How to parse API responses |
| `realtime` | RealtimeConfig | Optional upstream webhook and MoonShine refresh settings |
| `panel` | string | Panel name (URL prefix) |

Local Eloquent services are different: `initialize_local_service` writes a
lightweight service record with `kind: local` and `driver: eloquent`, but no
`base_url`, `api_key`, `response_mapping`, upstream auth, health endpoint, or
realtime contract. Local resources are native MoonShine `ModelResource`
classes generated by `create_model_resource`; REST data tools do not use them.

## Admin Auth And SSO

`auth_type` and `admin_auth_mode` are separate settings:

| Setting | Purpose |
|---------|---------|
| `auth_type` | How MoonShine V calls the upstream API after the panel is loaded |
| `admin_auth_mode` | How a human administrator signs in to the generated panel |

Supported panel login modes:

| Mode | Use when | Required config |
|------|----------|-----------------|
| `moonshine` | Local `moonshine_users` own admin access | none |
| `delegated_token` | Each admin already has an upstream PAT/API token | `admin_auth.validate_endpoint` |
| `oauth2_authorization_code` | The organization has an OAuth2/OIDC-compatible IdP and browser SSO is required | `admin_auth.authorize_url`, `admin_auth.token_url` |

The panel login page adapts to the selected mode. Token login masks the PAT,
preserves its case and accepts an omitted refresh token. OAuth mode shows a
sign-in button that starts Authorization Code + PKCE. Upstream login names are
not normalized as local email addresses. Failed login input never flashes a PAT
back into the form or stores it verbatim in a rate-limit key.

OAuth2 Authorization Code uses PKCE S256 and panel routes
`/<panel>/oauth/redirect` and `/<panel>/oauth/callback`. After the callback,
the upstream user is synced into `moonshine_users` and linked by
`moonshine_user_upstream_identities(provider_service, subject_id)`.

```php
'admin_auth_mode' => 'oauth2_authorization_code',
'oauth_client_id' => env('CRM_OAUTH_CLIENT_ID', ''),
'oauth_client_secret' => env('CRM_OAUTH_CLIENT_SECRET', ''),
'admin_auth' => [
    'authorize_url' => 'https://idp.example.com/oauth/authorize',
    'token_url' => 'https://idp.example.com/oauth/token',
    'scopes' => ['openid', 'profile', 'email'],
    'redirect_uri' => 'https://moonshine.example.com/crm-admin/oauth/callback',
],
```

Current limits: SAML-only SSO is not supported directly, and full OIDC
discovery/JWKS/ID-token validation is not a separate mode yet. The current SSO
path expects an OAuth2 Authorization Code flow plus an upstream identity
endpoint that can return the signed-in user's profile. If a user needs
SAML, OIDC discovery/JWKS, multi-provider chooser, or another enterprise SSO
protocol, ask them to open an issue in the project repository so we can evaluate adding it.

## OAuth rotation and record IDs

When re-registering a service, omitted secrets retain their stored values in
local and hosted modes. An explicit empty string clears a secret; required
OAuth/session credentials and enabled hosted webhook secrets still fail
validation if empty. Local `.env` serialization preserves literal dollar signs,
quotes, backslashes and control characters across reloads and re-registration.

Service OAuth refresh tokens are stored encrypted in the database, separately
for each tenant, service, administrator, client/token URL and initial seed.
Clearing application cache does not discard the latest rotation. Concurrent
refreshes use the configured cache store's atomic lock; use shared Redis for
multiple workers. A delayed 401 reuses a token another worker already refreshed.
Delegated browser credentials remain in their user's session and identity;
refresh never substitutes another user's cached token.

On upgrade, keep the old cache until refresh-token services have been exercised:
legacy cached rotations migrate on first use. A rotation already lost from the
old cache cannot be recovered; obtain a new seed from the upstream provider.

Record IDs and endpoint path placeholders are single URL segments. Empty values,
`.` / `..`, slashes, backslashes, percent escapes and control characters are
rejected with `VALIDATION` (HTTP 422 in the browser) before any upstream write.
Other opaque IDs are URL-encoded; mutation body values remain unchanged.

## ResponseMapping

The package is stack-free — it works with any API response format. `ResponseMapping` tells the caster where to find data in API responses.

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `dataKey` | string | `"data"` | JSON path to the data array |
| `totalKey` | string | `"total"` | JSON path to total items count |
| `perPageKey` | string | `"per_page"` | JSON path to per-page count |
| `currentPageKey` | string | `"current_page"` | JSON path to current page number |
| `lastPageKey` | string | `"last_page"` | JSON path to last page number |
| `perPageParamName` | string | `"per_page"` | Upstream request parameter for page size |
| `zeroBasedPages` | bool | `false` | Translate zero-based upstream pages to one-based UI/MCP pages |

## API Format Examples

### Laravel / standard

```json
{
  "data": [{ "id": 1, "title": "Hello" }],
  "total": 42,
  "per_page": 15,
  "current_page": 1,
  "last_page": 3
}
```

```php
new ResponseMapping(
    dataKey: 'data',
    totalKey: 'total',
    perPageKey: 'per_page',
    currentPageKey: 'current_page',
    lastPageKey: 'last_page',
)
```

### Django REST Framework

```json
{
  "count": 42,
  "next": "http://api.example.com/items/?page=2",
  "previous": null,
  "results": [{ "id": 1, "title": "Hello" }]
}
```

```php
new ResponseMapping(
    dataKey: 'results',
    totalKey: 'count',
    nextPageUrlKey: 'next',
    prevPageUrlKey: 'previous',
    perPageParamName: 'page_size',
)
```

The `django` registration preset includes these keys. Without `last_page`
metadata, the panel uses previous/next navigation from the response. It does not
guess the last page from the requested size: Django may use a fixed server-side
page size. Navigation stays on the panel URL, and MCP page numbers start at 1.
Re-register existing Django services with `response_format: "django"` to persist
the navigation mapping in older installations; omitted secrets are preserved.

### Express / NestJS (nested meta)

```json
{
  "data": [{ "id": 1, "title": "Hello" }],
  "meta": {
    "total": 42,
    "per_page": 10,
    "current_page": 1,
    "last_page": 5
  }
}
```

```php
new ResponseMapping(
    dataKey: 'data',
    totalKey: 'meta.total',
    perPageKey: 'meta.per_page',
    currentPageKey: 'meta.current_page',
    lastPageKey: 'meta.last_page',
)
```

### Spring Boot

```json
{
  "content": [{ "id": 1, "title": "Hello" }],
  "totalElements": 42,
  "size": 20,
  "number": 0,
  "totalPages": 3
}
```

```php
new ResponseMapping(
    dataKey: 'content',
    totalKey: 'totalElements',
    perPageKey: 'size',
    currentPageKey: 'number',
    lastPageKey: 'totalPages',
    perPageParamName: 'size',
    zeroBasedPages: true,
)
```

For MCP registration, use `response_format: "custom"` and the corresponding
snake_case keys, including `per_page_param_name: "size"` and
`zero_based_pages: true`. UI/MCP page 1 sends `page=0&size=25` upstream; response
`number: 0` becomes page 1 in the panel.

## Link-header pagination

Set `response_mapping.pagination_type` to `link_header` for APIs that return
`Link: <...page=2>; rel="next"` navigation. An optional `total_header` maps a
record-count header such as `X-Total-Count`; without `rel="last"`, the panel uses
previous/next navigation.

Only the page number is read from upstream links. Browser links stay inside the
panel, keep the current filters, search and sort, and use the service's server-side
authentication. Upstream hosts, paths and other query parameters are not copied
into browser navigation. Missing or invalid page numbers produce no link.

## Cross-Service Relations

Relation fields normally use the parent resource service. Add
`target_service` to a relation field spec when the related data belongs to
another registered service:

```json
{
  "service": "blog",
  "name": "post",
  "endpoint": "/posts",
  "fields": [
    { "column": "id", "type": "id" },
    {
      "column": "brand_id",
      "type": "belongs_to",
      "target_service": "shop",
      "endpoint": "/brands",
      "label_key": "name"
    }
  ]
}
```

The target service is resolved through its `ServiceConfig`, so its base
URL, auth type, OAuth/session state, retry behavior, and
`ResponseMapping` are reused. The parent service only supplies the parent
item and placeholder context. Field-local `dataWrapper()` /
`data_wrapper` still overrides the target service `dataKey` when a
single relation endpoint has a different envelope.

Same-service relations should omit `target_service`. Cross-service
`has_one` and `has_many` fields support field-level list, preview,
create, update, and delete calls; generated nested relation resources are
still same-service only.

## config/api-admin.php

The package configuration file:

```php
return [
    // Legacy/static service configuration. MCP registrations live in
    // storage/api-admin/generated/services.php instead.
    'services' => [
        // 'backoffice' => [
        //     'name' => 'backoffice',
        //     'kind' => 'local',
        //     'driver' => 'eloquent',
        //     'panel' => 'admin',
        //     'title' => 'Backoffice',
        // ],
    ],

    // REST resources generated by create_resource
    'resources_path' => env('API_ADMIN_RESOURCES_PATH', app_path('MoonShine/ApiAdmin/Resources')),

    // Local Eloquent resources generated by create_model_resource
    'local_resources_path' => env('API_ADMIN_LOCAL_RESOURCES_PATH', app_path('MoonShine/Resources')),
    'local_resources_namespace' => env('API_ADMIN_LOCAL_RESOURCES_NAMESPACE', 'App\\MoonShine\\Resources'),

    // Hosted mode. Local/self-hosted mode remains the default.
    'hosted' => [
        'mode' => env('API_ADMIN_HOSTED_MODE', 'local'),
        'tenant_header' => env('API_ADMIN_TENANT_HEADER', 'X-ApiAdmin-Tenant'),
        'route_prefix' => env('API_ADMIN_TENANT_ROUTE_PREFIX', 't/{tenant}'),
        'tenant_path_segment' => env('API_ADMIN_TENANT_PATH_SEGMENT', 'Tenants'),
        'operations' => [
            'recommended_cache_store' => env('API_ADMIN_HOSTED_CACHE_STORE', 'redis'),
            'recommended_session_driver' => env('API_ADMIN_HOSTED_SESSION_DRIVER', 'redis'),
            'recommended_queue_connection' => env('API_ADMIN_HOSTED_QUEUE_CONNECTION', 'redis'),
            'recommended_broadcast_connection' => env('API_ADMIN_HOSTED_BROADCAST_CONNECTION', 'reverb'),
            'smoke_timeout_seconds' => env('API_ADMIN_HOSTED_SMOKE_TIMEOUT', 30),
        ],
        'mcp' => [
            'enabled' => env('API_ADMIN_HOSTED_MCP_ENABLED', false),
            'route' => env('API_ADMIN_HOSTED_MCP_ROUTE', 'api-admin/mcp'),
        ],
    ],

    // Global realtime defaults. Per-service `realtime` overrides are
    // created by register_service.
    'realtime' => [
        'enabled' => false,
        'webhook_secret' => '',
        'refresh_strategy' => 'auto',
    ],
];
```

## Hosted Operations

Hosted mode is enabled with `API_ADMIN_HOSTED_MODE=hosted`. Tenant identity is
carried by the route prefix, for example `/t/{tenant}/admin` and
`/t/{tenant}/api-admin/mcp`; `API_ADMIN_TENANT_HEADER` remains available for
internal HTTP boundaries that do not have a route parameter.

Production hosted installs should use shared, server-side infrastructure:

| Setting | Recommended | Why |
|---------|-------------|-----|
| `CACHE_STORE` | `redis` or another shared cache | OAuth/session auth, health snapshots, instructor state, and reload coordination must survive multiple workers |
| `SESSION_DRIVER` | `redis` or `database` | Delegated admin login and MoonShine browser sessions must be server-side and tenant-scoped |
| `QUEUE_CONNECTION` | `redis`, `database`, or another async driver | Provisioning, reload, and future long-running generation work should not block hosted HTTP requests |
| `BROADCAST_CONNECTION` | `reverb`, Pusher-compatible, or another real broadcaster | Realtime refresh events must be delivered to tenant-scoped channels |

`health_check({})` includes a `diagnostics` block with the active mode,
tenant id, configured backends, and warnings for degraded hosted defaults such
as `array`, `file`, `cookie`, `sync`, `log`, or `null`. These warnings are
also logged without token values or upstream credentials.

## Realtime Webhooks

Realtime upstream updates are configured per service under `realtime`.
Laravel Reverb is the recommended WebSocket backend; configure Reverb,
broadcasting, and Echo with the standard Laravel settings. The package uses
Laravel broadcasting abstractions and falls back cleanly when no broadcaster is
configured.

```php
'services' => [
    'blog' => [
        'name' => 'blog',
        'base_url' => env('BLOG_API_URL', 'https://api.blog.example.com/v1'),
        'realtime' => [
            'enabled' => true,
            'webhook_secret' => env('BLOG_WEBHOOK_SECRET', ''),
            'webhook_signature_header' => 'X-ApiAdmin-Signature',
            'webhook_signature_algo' => 'sha256',
            'webhook_event_key' => 'event',
            'webhook_resource_key' => 'resource',
            'webhook_action_key' => 'action',
            'webhook_id_key' => 'id',
            'allowed_events' => ['created', 'updated', 'deleted', 'upserted'],
            'refresh_debounce_ms' => 750,
            'refresh_strategy' => 'auto',
            'sensitive_payload_keys' => ['password', 'token', 'secret', 'api_key', 'authorization'],
        ],
    ],
],
```

Webhook endpoint: `POST /api-admin/webhooks/{service}`.

`refresh_strategy` controls browser behavior for matching mutations:
`auto` reloads list/detail pages and shows a notice on forms, `notice` only
shows the notice, and `disabled` suppresses browser refresh.

Hosted realtime requires a nonempty `webhook_secret`; missing or empty secrets
are rejected both at registration and when receiving a webhook. An omitted
secret is preserved on re-registration. To clear it, disable realtime first.
Local mode retains optional unsigned webhooks for trusted development.

Hosted refresh events use private tenant/service channels. Echo uses its standard
`/broadcasting/auth` endpoint with the browser session and CSRF token. Subscription
requires the service panel's signed-in user and an active tenant membership;
revoked memberships and inactive tenants are denied. Local channels remain public.
Configure the Laravel broadcaster and Echo before enabling realtime; the default
installation does not run a WebSocket server.
Keep this application's `/broadcasting/auth` route; do not register Laravel's
generic broadcast-auth route over it when installing a broadcaster.

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `API_ADMIN_RESOURCES_PATH` | `app/MoonShine/ApiAdmin/Resources` | REST resource output root for `create_resource` |
| `API_ADMIN_LOCAL_RESOURCES_PATH` | `app/MoonShine/Resources` | Local Eloquent `ModelResource` output root for `create_model_resource` |
| `API_ADMIN_LOCAL_RESOURCES_NAMESPACE` | `App\MoonShine\Resources` | Namespace matching the local resource output root |
| `API_ADMIN_HOSTED_MODE` | `local` | Set to `hosted` to require tenant context before service, panel, MCP, and generated-state access |
| `API_ADMIN_TENANT_ROUTE_PREFIX` | `t/{tenant}` | Hosted route prefix for tenant-scoped admin and MCP endpoints |
| `API_ADMIN_TRUSTED_PROXIES` | empty | Comma-separated trusted ingress IPs/CIDRs for client IP forwarding; never `*` |
| `API_ADMIN_HOSTED_MCP_ENABLED` | `false` | Enables the hosted Streamable HTTP MCP transport routes |
| `API_ADMIN_HOSTED_CACHE_STORE` | `redis` | Documented target cache store used by operational diagnostics |
| `API_ADMIN_HOSTED_SESSION_DRIVER` | `redis` | Documented target session driver used by operational diagnostics |
| `API_ADMIN_HOSTED_QUEUE_CONNECTION` | `redis` | Documented target queue connection used by operational diagnostics |
| `API_ADMIN_HOSTED_BROADCAST_CONNECTION` | `reverb` | Documented target broadcaster used by operational diagnostics |
| `LOG_LEVEL` | Laravel default | Set to `debug` while diagnosing relation target resolution; use `info` or higher in production to reduce verbose relation traces |
| `<SERVICE>_WEBHOOK_SECRET` | empty | Per-service HMAC secret for realtime upstream webhooks |
